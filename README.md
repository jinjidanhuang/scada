> **项目愿景：推动工业物联网与数字化技术在中小矿山企业的务实落地。**  
> 针对砂石骨料、金属选矿、洗煤选炭、地下井工与露天采矿等中小矿山企业，降低传统商业 SCADA 系统的软硬件投入与专业 IT 运维门槛，适应矿区弱网或内网隔离环境，提供一套**易于部署、资源占用可控、支持纯内网运行、具备 3D 数字孪生可视化能力**的工业物联管控平台。

---

## 一、 为什么中小矿山需要这套系统？

在实际矿山与选矿厂一线，设备运转与安全生产往往面临以下典型痛点：
1. **异构控制系统混杂**：粗破机、颚破、圆锥破采用西门子 PLC，振动筛和给料机通过 Modbus 网关接入，总降变电所采用 DL/T 645 电能表，各厂家协议不统一，数据难以汇总；
2. **设备运行状态缺乏实时监测**：破碎机过载、球磨机主轴承温度异常升高、胶带输送机跑偏等工况，若仅依赖人工巡检，难以及时发现异常；
3. **矿区网络条件受限**：选厂和矿井多位于山区或地下，外网连接不稳定甚至处于纯内网隔离状态，依赖公有云的 SaaS 系统在断网时无法正常工作；
4. **能耗与生产核算粗放**：吨矿电耗、破碎与磨矿工段峰谷平电费占比缺乏细化统计，排产计划与实际设备运转率难以对齐。

**本系统无需改动现场原有电气控制回路，通过一台普通工控机或本地服务器，即可实现车间设备的数据采集、状态监控、指标核算与三维可视化管理。**

## 二、 核心系统功能架构

### 1. 异构 PLC 与边缘网关多协议采集
* **支持主流工业通信协议**：
  * **Siemens S7 协议**：支持连接 S7-200 SMART、S7-1200、S7-1500，读取 I/Q/M 区及 DB 数据块；
  * **Modbus TCP / RTU**：接入现场传感器总线、温度巡检仪、变频器及串口服务器；
  * **DL/T 645 / DL/T 698 规约**：采集总降压站与配电室有功电量、视在功率、三相电流电压。
* **配置在线热重载**：测点映射配置文件（`plc_config.json`）修改后由文件系统事件监听器（Watchdog）自动感知并重新加载，无需重启整体服务。
* **断线自动重连与退避机制**：针对工业现场网络波动导致的连接中断，采集驱动支持自动重连与连接状态恢复。

### 2. 选矿车间产线 3D 数字孪生监控座舱 (Three.js / WebGL)
* **生产场景三维还原**：在浏览器端呈现粗破受料仓、给矿皮带、振动筛、球磨系统、浮选机、浓密机等关键生产单元的三维运行态势。
* **点位数据空间化映射**：
  * 电机运行/停止/故障状态实时映射至 3D 模型颜色（绿/红/黄状态提示）；
  * 轴承测温点、振动幅值、润滑油压、料仓料位等实时数据悬浮标定于对应设备部位；
  * 支持产线视角巡检与报警设备聚焦定位。

### 3. WebRTC 低延迟工业视频联动 (MediaMTX 架构)
* 针对矿山局域网多路视频调阅场景，系统集成流媒体转发服务；
* 将受料斗监控球机、皮带转运点枪机等现场摄像头的 RTSP 视频流转换为 **WebRTC 协议**；
* 浏览器端无需安装专用插件即可直接播放，支持工艺报警发生时联动调取对应工位实时视频画面。

### 4. 工艺越限告警与闭环管理
* **分级预警机制**：支持配置高限、低限、多条件组合及状态变化等报警规则；
* **异常毛刺过滤**：对瞬时通信读取异常进行过滤，减少无效误报；
* **报警记录与通知**：触发页面声光提示，记录报警产生时刻、确认状态与恢复时刻，支持对接飞书或企业微信群机器人消息推送。

### 5. 生产排产、OEE 稼动率与吨矿能耗归档
* **生产线 OEE 统计**：支持时间开动率、性能稼动率等多维度指标汇总；
* **吨矿单耗核算**：结合小时级电表读数与产量数据，生成班次、日度与月度能耗分析报表；
* **报表导出**：支持将生产与能耗明细导出为 CSV 表格文件，便于生产调度复盘。

### 6. 边缘本地缓存与断网续传
* 采用 **高速内存数据总线 + SQLite 本地环形缓存（`edge_buffer`）**；
* 当上层数据库或外网链路中断时，边缘侧可将采集数据暂存至本地缓存库，待链路恢复后按序补传并重算汇总指标。

## 三、 运行环境要求与一键部署

### 1. 硬件架构与系统兼容性
* **CPU 处理器架构**：
  * **标准支持 `x86_64` (`amd64`)**：预构建离线镜像与 Cython `.so` 二进制内核基于 x86_64 编译，全面支持 **Intel / AMD** 处理器的工控机、商用台式机、机架服务器，以及主流 x86 NAS 硬件（如飞牛 OS、群晖、威联通、1Panel 等）与虚拟化环境（VMware / PVE / ESXi）。
  * **ARM 架构说明**：若硬件采用 ARM64 (`aarch64`) 芯片（如工控边缘计算盒、树莓派、国产 ARM 服务器），需在对应架构环境下编译生成对应镜像。
* **操作系统兼容性**：
  * 容器自带完整的 Debian 12 基础运行环境与 Python 3.12 运行栈，与宿主机环境完全解耦，宿主机无需安装 Python 或数据库。
  * 完美适配 **Ubuntu**、**Debian**、**CentOS / Rocky Linux**、**飞牛私有云 (fnOS)**、**群晖 DSM** 等所有支持 Docker 的 Linux 发行版。
* **建议配置**：4 核 CPU、8GB 内存、64GB 可用存储空间以上。

### 2. 命令行一键极简部署（全自动）
本项目已内置自动化安装与运维脚本，自动完成镜像载入、目录初始化与集群编排启动：
```bash
# 1. 赋予执行权限
chmod +x install.sh stop.sh

# 2. 一键启动服务（自动识别离线 images.tar 或在线环境）
./install.sh
```

* **一键停止服务**：
```bash
./stop.sh
```

### 3. NAS 可视化面板部署（飞牛 OS / 群晖 / 1Panel）
若采用 NAS 系统的 WebUI 图形化界面管理：
1. **载入镜像**：在 NAS 的「Docker 镜像管理」中点击导入 `images.tar` 离线镜像包；
2. **创建项目**：进入「Compose / 容器编排」功能，新建项目并粘贴本项目根目录下的 `docker-compose.yml` 内容；
3. **直接启动**：系统仅对 `./data` 与 `./logs` 目录进行映射，首次启动容器会自动释放初始数据库与配置文件，完全规避了单文件误建为空目录的兼容性问题。

### 4. 浏览器访问入口
系统默认映射宿主机 **`18080`** 端口（避开 8000 / 8080 等 NAS 系统自带端口冲突）：
* **3D 选矿数字孪生座舱**：`http://<服务器或NAS_IP>:18080/monitor/`
* **智能运营与设备管理后台**：`http://<服务器或NAS_IP>:18080/admin/`

## 四、 核心目录与持久化文件说明

系统采用**目录挂载（`./data` 与 `./logs`）+ 首次启动自动释放初始数据**机制。容器首次启动后，会在当前目录的 `./data/` 下自动生成运行所需的数据文件：

| 路径 / 文件 | 作用与维护说明 |
| :--- | :--- |
| **`install.sh` / `stop.sh`** | 一键极简部署与启停脚本，自动化完成环境诊断与服务拉起。 |
| **`docker-compose.yml`** | 标准 Docker Compose 编排文件，默认挂载 `./data` 与 `./logs`，映射 `18080` 端口。 |
| **`./data/db.sqlite3`** | 首次启动时自动从镜像释放的初始数据库文件，后续设备台账、测点配置与历史记录均持久化于此。 |
| **`./data/plc_config.json`** | 现场 PLC IP、端口、协议类型与测点地址映射文件，在后台管理界面修改设备配置后会自动同步更新。 |
| **`./data/license.lic`** | 离线授权文件存放路径。未放置该文件时系统以**受限试用模式**运行；获取授权文件后直接放入 `./data/` 目录即可生效。 |
| **`./logs/`** | 采集日志（`caiji.log`）、数据同步日志（`mysql_sync.log`）与告警引擎日志（`alarm_engine.log`）存放目录。 |

## 五、 离线授权机制与技术支持

本系统核心业务模块通过 Cython 编译为二进制扩展（`.so`），并采用 **RSA-2048 非对称数字签名** 进行本地离线授权校验，运行期间无需连接外部授权服务器。

* **社区试用模式**：未配置 `license.lic` 时，系统默认开启受限试用模式（支持接入 1 台网关、20 个测点），便于企业进行前期功能验证与产线联调；
